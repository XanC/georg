# Georg

Georg is an open-source, self-hosted application that turns recordings of Christian worship services into publishable sermons: it finds the sermon in a service recording, extracts the audio, transcribes and formats it, proposes metadata, lets a person review and correct everything, and then publishes the approved result through output modules (the first one targets WordPress sites using ChurchThemes' Church Content plugin).

> **Status:** early development. Nothing is usable yet. See [docs/architecture.md](docs/architecture.md) for the design.

## Why "Georg"?

The project is named for **Georg Rörer (1492–1557)**, who recorded and preserved many of Martin Luther's sermons. Georg does a modern version of his work: capturing sermons so they can be kept and shared.

## Design in brief

- One Python application (FastAPI web UI + background worker), one container image.
- SQLite database and a local or S3-compatible artifact store.
- Interchangeable modules for **inputs** (e.g. Google Drive, uploads), **processors** (audio classification, sermon detection, transcription, formatting, metadata) and **outputs** (e.g. WordPress).
- Every processing stage keeps its intermediate results; a person approves a specific version before anything is published.

Georg was first built for one Lutheran congregation, but it avoids denomination-specific assumptions so other congregations can deploy and extend it.

## Installation

Not yet available. Development setup:

```sh
uv sync
uv run pytest
```

Requires Python 3.12+ and FFmpeg.

To try the processing stages on a recording without the database, copy
`georg.example.toml` to `georg.toml` and run:

```sh
uv sync --extra classify --extra whisper
uv run georg run part1.mp4 part2.mp4 --out out/ --date 2026-11-01 --no-format
```

This writes the three MP3 renditions, the sermon transcript, and `report.json`
with the detected boundaries. Classification and transcription are cached, so
re-running with `--boundaries 0:02:10,0:31:20,0:52:05,1:14:30` only re-cuts the audio.

With the database: `uv run georg discover` records new recordings from the
configured inputs and queues them, and `uv run georg worker` processes the queue,
storing the renditions and a proposed sermon revision for review. A
`local_folder` input (one subfolder per service) works without Google Drive.

Reviewers work in the web UI: add an account with
`uv run georg user add alice --role reviewer` (prompts for a password), then start
it with `GEORG_SECRET_KEY=<random string> uv run georg web` and open
<http://127.0.0.1:8000>. There a reviewer listens to the renditions, corrects the
boundaries, metadata, and transcript (each save is a new revision; moved boundaries
re-render the audio), and approves a revision for publishing. `georg web --dev`
uses a throwaway key and allows session cookies over plain HTTP; otherwise serve
it behind HTTPS.
